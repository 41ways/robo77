# 로보77

합을 계속 더해 가다가 **77 이상**이 되거나 **11의 배수**를 밟으면 하트를 잃는 온라인 카드 게임. 2~6인.

## 실행

```bash
npm install     # 최초 1회
npm start       # http://localhost:8790
```

## 친구와 하기

### 같은 와이파이

서버를 켠 뒤 친구에게 **`http://<내 IP>:8790`** 을 알려준다.
IP 확인: `ipconfig getifaddr en0`

macOS가 "들어오는 연결을 허용하시겠습니까?" 라고 물으면 **허용**을 눌러야 한다.

### 다른 네트워크 (외부 인터넷)

```bash
npx cloudflared tunnel --url http://localhost:8790
```

출력되는 `https://....trycloudflare.com` 주소를 공유하면 된다.
터미널을 끄면 주소도 사라진다. (WebSocket을 그대로 통과시키므로 게임이 정상 동작한다.)

### 배포 (Render)

`render.yaml` 이 들어 있어서 Render가 설정을 알아서 읽는다.

1. GitHub에 push
2. [dashboard.render.com](https://dashboard.render.com) → **New → Blueprint**
3. `41ways/robo77` 저장소 선택 → **Apply**

빌드가 끝나면 `https://robo77-xxxx.onrender.com` 주소가 나온다. 그 주소를 친구에게 주면 끝.
이후에는 `main`에 push할 때마다 자동으로 다시 배포된다.

무료 플랜은 **15분 동안 아무도 안 들어오면 잠들고**, 그 뒤 첫 접속이 40~60초 걸린다.
같이 하기로 한 시간 조금 전에 미리 한 번 열어두면 깨어 있는 상태로 시작할 수 있다.

## 규칙

시작할 때 카드 **5장**과 하트 **3개**를 받는다.

- 돌아가면서 카드를 한 장씩 낸다. 낸 숫자가 하나의 **합**에 계속 더해진다
- **합이 77 이상**이 되면 하트를 하나 잃고 그 라운드가 끝난다
- **합이 11의 배수**(11·22·33·44·55·66)가 되어도 하트를 잃는다. 0은 판의 출발점이라 세지 않는다
- **제한 시간**을 넘겨도 하트를 잃는다 (5·10·15초·무제한 중 방장이 고른다)
- 카드를 내면 곧바로 한 장을 채워 늘 5장을 들고 있다
- 라운드가 끝나면 카드를 모두 모아 다시 섞고 5장씩 나눈다. **새 라운드의 선은 직전 선의 왼쪽 사람**
- 하트를 다 잃어도 계속 한다. **하트가 0인 상태에서 또 잃어야 탈락**
- 마지막까지 남은 한 명이 승리

### 카드 56장

| 카드 | 하는 일 | 장수 |
|---|---|---|
| 2~9 | 그대로 더한다 | 각 3장 |
| 10 | 그대로 더한다 | 8장 |
| 0 | 합은 그대로. 단 **계산은 거치므로** 합이 이미 11의 배수면 죽는다 | 4장 |
| 11·22·33·44·55·66 | 한 방에 11의 배수를 만드는 자살 카드 | 각 1장 |
| -10 | 10을 뺀다. 합이 9 이하면 음수가 된다 | 4장 |
| 76 | 76을 더한다. **합이 0 이하일 때만** 낼 수 있다 | 1장 |
| ×2 | **다음 사람이 두 장**을 내야 한다. 합은 안 변한다 | 4장 |
| 방향전환 | 방향을 뒤집는다. **계산을 안 거쳐서 11의 배수여도 안전** | 5장 |

`×2`와 `방향전환`은 라운드의 첫 장으로 낼 수 없다.

76을 맞은 다음 사람이 살아남는 길은 `0` · `×2` · `방향전환` 셋뿐이다.
`-10`은 76-10 = **66**이라 11의 배수로 죽는다.

## 난이도 — 숫자 합 공개

대기실의 토글로 켜고 끈다.

- **켜면** 합이 화면 한가운데 뜬다. 처음 하는 사람용
- **끄면** 합이 `?` 로 가려지고, 맨 위에 놓인 카드 한 장만 보인다.
  머릿속으로 계속 더해 가야 하고 11의 배수를 헛디디는 일이 훨씬 잦아진다

판정은 어느 쪽이든 서버가 한다. 토글은 **합을 보여줄지 말지**만 정한다.

## 구조

```
rules.js    덱 · 낼 수 있는지 · 판정 (순수 함수, 서버와 테스트가 같이 씀)
server.js   정적 서빙 + WebSocket. 손패 · 합 · 타이머 · 봇을 전부 서버가 쥔다
public/     화면 (index.html · style.css · app.js)
test/       rules.js 규칙 단위 테스트 · flow.js 서버를 띄워 판을 끝까지 돌리는 테스트
```

클라이언트는 판정을 하지 않는다. "이 카드 낼래" 만 보내고 나머지는 서버가 정한다.
합을 숨기는 모드에서는 **서버가 합을 아예 내려보내지 않으므로** 개발자 도구로도 볼 수 없다.

## 테스트

```bash
npm test
```

규칙 단위 테스트와, 실제로 서버를 띄워 2·4·6인 판을 끝까지 돌리는 통합 테스트가 함께 돈다.
`ROBO_FAST=1` 을 주면 봇이 뜸을 들이지 않아 판이 빨리 끝난다.
